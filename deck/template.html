Process · Options · 6 / 7

Option A and Option B: two ways to move a project

Option A · keep the source compute

  • The source platform keeps running the schedule, with Platform B compute for the SQL steps.
    • The connection is set up once per workspace.
    • Platform B costs apply from the first day.
  • Visual and SQL steps run in the database through the connection.
  • Scripts keep running on the source platform.
    • Outputs are reconciled every day during the transition.

Option B · rebuild project by project

  • Each project is rebuilt as SQL, notebooks, or pipelines and jobs.
    • Each step gets one target and one command (slide 3).
  • Waves follow business domains, starting with a pilot project end to end.
  • The two options can be combined per project.
Where Platform B helpsPlatform B can help measure cost, run time and gaps for each option during the pilot.

Next steps · 7 / 7

Next step: pilot one project end to end

Prepare and rebuild

  • Inventory the project through the API, export its definition as a backup, and score it.
  • Set up access, storage and a connection for the source data.
  • Convert the file datasets in place, and set up a federated catalog for the database sources.
  • Rewrite SQL-capable steps as SQL; move the other steps to scripts.
  • Keep dependencies in the environment, without the platform runtime package.

Deliver, compare and cut over

  • Export each saved model to the registry, or retrain it; register it with its input schema.
  • Build the pipeline and the job, with checks for each source check.
  • Grant access per group; deploy dev and prod from one bundle.
  • Compare each output with the source, both ways, plus keys and aggregates.
  • Run both paths in parallel for the agreed cycles, rehearse the rollback, then cut over.
Next step Agree the pilot project and its success measures with the customer owner, then run the inventory.
